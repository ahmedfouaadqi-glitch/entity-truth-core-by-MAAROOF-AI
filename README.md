# Entity Truth Core by MAAROOF AI

[![CI](https://github.com/ahmedfouaadqi-glitch/entity-truth-core-by-MAAROOF-AI/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/ahmedfouaadqi-glitch/entity-truth-core-by-MAAROOF-AI/actions/workflows/ci.yml)

A free, open-source, local-first utility for preparing a clearer machine-readable entity profile. It provides a deterministic TypeScript core, a local CLI, an MCP server and Agent Skills for compatible coding agents.

## What it does

1. Scans a selectable window of 100 or 500 lexical words, or all supplied text (`100` remains the default), for candidate dates, percentages, standards, scale and currency patterns.
2. Provides a limited Arabic, Sorani Kurdish and English name-word-list heuristic.
3. Generates draft Schema.org Organization JSON-LD and an llms.txt-style profile from user-supplied information.
4. Performs a limited local structural check of the Organization JSON-LD subset generated by this project.
5. Exposes the same core through local MCP tools, CLI functions and the browser playground.

## What it deliberately does not do

- It does not search the web, crawl company websites, or fetch external sources.
- It has no external verification mode and does not compare user inputs with websites, registries, or third-party databases.
- It does not independently verify facts, trademarks, legal ownership or official social profiles.
- It does not perform global name-collision research.
- It does not query AI models or measure SEO, GEO, AI recommendations, citations or rankings.
- It does not analyse competitors or create an optimization strategy.
- It does not connect to MAAROOF AI's production platform, models, tools, orchestration, databases or credentials.
- It does not infer Worldwide coverage or claim that an entity is verified.

This utility prepares. It does not investigate. Signals and scores are heuristics, not truth, ranking or visibility measurements. JSON-LD validation is limited to a small locally checked subset, not full Schema.org validation. The binding product boundaries are documented in [Product Scope](docs/PRODUCT_SCOPE.md).

## Requirements

Node.js 20 or newer. CI uses Node.js 22.

## Install, build and test

From a local checkout:

    npm install
    npm run build
    npm test

## Local CLI

    node dist/cli.js "Example Company" --text "Founded in 2018, ISO 9001 certified." --lang en --window 500 --out-dir ./entity-profile

Or pass a JSON file containing name, optional URL and description, user-supplied markets, entity languages and opening text:

    node dist/cli.js --input ./entity.json --json

Use `--window 100`, `--window 500`, or `--window full` to choose the scan window. The default is `100`. The same `window` field is accepted in JSON input and by the local MCP `entity_scan` tool. The output directory contains audit-report.json, organization.jsonld and llms.txt. Existing files are not overwritten unless --force is supplied.

## MCP server

The local MCP server exposes four tools:

| Tool | Purpose |
|---|---|
| entity_scan | Complete local audit and draft generation |
| entity_name_hint | Limited static name heuristic |
| entity_profile_generate | Draft JSON-LD and llms.txt-style profile |
| entity_profile_validate | Limited local structural JSON-LD check |

Run after building:

    node dist/mcp/server.js

The server uses local stdio. It does not open an HTTP port or connect to a remote service. See docs/INTEGRATIONS.md for Codex, Claude Code and other compatible clients.

## Agent Skills

Skills are included in:

- .agents/skills/entity-truth-core/SKILL.md for Codex.
- .claude/skills/entity-truth-core/SKILL.md for Claude Code.
- skills/entity-truth-core/SKILL.md as the canonical distributable copy.

The copies are regression-tested to prevent instruction drift. Other agents can use the same skill format when they support Agent Skills discovery.

A model without an agent runtime, MCP client, filesystem access or command execution cannot invoke local tools by itself. Compatibility depends on the host application, not merely the model name.

## Run the browser playground locally

Build first, then serve the repository root over HTTP (do not open the HTML directly with file://):

    npm run build
    python -m http.server 8000

Open http://localhost:8000/playground/. The page imports the compiled core from dist/; it does not maintain a second scanner implementation.

## Deploy on your own hosting account

Build the static output:

    npm run build
    npm run prepare:pages

The generated _site/ directory contains only the static page and the compiled core. Deploy that directory to hosting you own. Templates and exact settings are documented in docs/DEPLOYMENT.md.

## Supported interface and analysis languages

- Arabic (ar)
- Sorani Kurdish (ku)
- English (en)

Language coverage is limited to the built-in heuristics and UI; it is not comprehensive NLP.

## Privacy

The core performs deterministic local processing. The browser playground processes entity data in the browser. The MCP server communicates with its host over local stdio. No entity input is sent to MAAROOF AI or a hosted processing service.
